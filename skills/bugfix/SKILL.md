# Bug 修复

## 触发条件
描述了一个 bug / 异常 / 报错 / 行为不符合预期。

## 执行流程

1. **定位问题** — 分析错误信息/现象，定位到具体代码位置
2. **说明原因** — 简要说明 root cause（1-3 句话）
3. **直接修复** — 输出修复代码，最小改动原则
4. **告知影响** — 说明改动影响范围，是否有副作用

## 不需要

- 需求拆解
- 工时预估
- Figma 解析
- 结构化 Plan
- 提效记录（除非负责人要求记录到 Bug 修复有效率表）

## 调试定位方法

1. **日志/堆栈分析** — 先看错误堆栈，定位到最近的业务代码帧
2. **状态检查** — 检查当前数据流/状态是否符合预期
3. **二分排查** — 改动范围大时通过 git bisect 或注释代码二分定位
4. **平台差异** — 仅单平台复现时，优先排查原生桥接/平台特有行为
5. **网络/数据问题** — 检查 API 返回结构是否变更，请求参数是否正确

## 原则

- **最小改动** — 只改必要的代码，不要顺手重构
- **定位 root cause** — 修上游问题，不在下游打补丁
- **说清影响** — 改动是否影响其他模块/页面
- **提供复现验证方式** — 告知如何验证修复有效

## 回归验证

修复完成后必须告知负责人：
- 复现路径（操作步骤）
- 预期修复后的行为
- 可能受影响的关联功能（需额外验证的地方）

## UI 布局类 Bug 定位

- 先区分父约束、子元素尺寸和溢出策略，避免只调整 magic number。
- 屏幕适配单位只负责尺寸换算，不等于自适应；动态内容、长文案、短屏、键盘和安全区仍需真实父约束。
- 空态或居中内容应依据实际剩余空间布局，避免“屏幕高度减固定常量”。
- SVG/小图标按钮分别检查外层按钮/交互区域和内部图标视觉尺寸；只固定局部元素，不让图标继承 stretch、弹性填满或无界约束。
- 卡片、SKU、弹窗和文案区优先移除无依据的固定整体高度，改用 padding、最小/最大约束、弹性布局、换行或滚动兜底。
- 固定底栏造成遮挡时，同时检查滚动内容预留空间和安全区。
- 回归至少覆盖原复现设备、窄屏/短屏和最长多语言，确认无溢出、遮挡、跳动或异常留白。
