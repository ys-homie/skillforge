# 生成实现 Plan

## 触发条件
需求拆解 + Figma 解析完成后，生成实现 Plan 供负责人审核。

## Plan 与截图存放规则

- Plan、配套 UI 验收清单、Figma 参考截图、实现截图/录屏和验收证据属于本地任务产物，默认不进入 Git 待提交变更或暂存区；无需为这些产物创建提交。
- 优先保存到当前任务可写的仓库外持久目录，按任务分目录组织；没有此类目录时可使用系统临时目录，并告知负责人该目录可能被系统清理。已有产物位于仓库内且已被 Git 忽略时可沿用。
- 在 Plan 中记录产物目录和截图/清单路径，在交付回复中提供可点击的绝对路径链接；后续实现与 UI 验收沿用该目录，冻结清单和首次验收基线仍需正常保留。
- 不将这些产物列入下方“需要创建/修改的文件”代码变更清单，不执行 `git add` 或 `git add -f` 将其加入暂存区。即使负责人要求提交业务代码，也默认排除这些产物；只有明确要求将这些产物纳入版本控制时才包含。
- 新生成产物后使用 `git status --short` 检查，避免新增未忽略的 Plan 或截图留在仓库中。不要为此自动取消已有文件的跟踪、撤销暂存或删除已有产物。
- 正式被应用引用的切图资源仍放在项目规定的资源目录并列入代码变更清单，不属于上述截图证据。

## 注意事项
- **Plan 是确认文档**，必须经负责人审核后才能进入代码实现
- Figma 链接必须保留在 Plan 中，便于后续回溯
- 参考代码路径要具体到文件，不要泛泛而谈
- 屏幕适配单位只负责尺寸换算，不等于自适应；Plan 必须明确真实父约束和溢出策略
- 页面、卡片、弹窗、面板和文案区默认宽度受父约束、高度由内容撑开；图标/SVG、头像、插画、缩略图、拖拽条、角标和明确尺寸的小按钮可局部固定宽高
- 小型 SVG/图标按钮必须区分外层按钮/交互区域与内层图标视觉尺寸，避免资源被父布局拉伸
- 颜色必须映射到项目颜色管理

## 复杂度评估

在 Plan 末尾标注整体复杂度，辅助负责人判断优先级：

| 复杂度 | 判断标准 | 预期 AI 完成度 |
|---|---|---|
| ⭐ 简单 | 纯 UI + 简单逻辑，有现成参考 | 90%+ 一次完成 |
| ⭐⭐ 中等 | 需要新状态管理 + API 对接，有部分参考 | 80%+ 可能需 1-2 轮微调 |
| ⭐⭐⭐ 复杂 | 涉及动画/原生交互/复杂状态，无直接参考 | 60-80% 需多轮迭代 |
