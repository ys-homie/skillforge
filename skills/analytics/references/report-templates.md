# 埋点交付文档模板

按实际范围填表；不适用字段写明原因，不编造数据。两份文档使用相同需求编号，代码证据写实际路径和行号。

## analytics-risk.md

```markdown
# [任务名] 埋点对比与风险

- 需求来源：[URL / 工作表 / 版本 / 页面 / 行号 / 读取时间]
- 代码基准：[仓库路径 / 分支 / HEAD / 应用版本与 build / 时间]
- 起始工作区：[相关已有 diff 摘要，说明与 HEAD 的差异]
- 分析范围：[包含与排除的需求项]

## 事件与属性对比

| 编号/原表行号 | 事件/场景 | 需求属性及类型/单位/枚举 | 当前值与来源/层级 | 存在性及差异 | 代码/字典证据 | 处理方案 |
|---|---|---|---|---|---|---|

## 风险与处理

| 风险编号 | 关联需求 | 具体冲突/触发条件 | 影响与等级 | 证据 | 处理方案 | 是否需要确认及原因 |
|---|---|---|---|---|---|---|

## 开发范围与待确认项

- 可直接实施：[编号及改动]
- 需确认：[具体问题、建议、受影响项；没有则写无]
- 未验证边界：[例如平台属性字典或历史看板未取得]
```
