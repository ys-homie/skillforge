# 代码实现

## 触发条件
负责人确认 Plan 后，按 Plan 逐步实现代码。

## 执行流程

1. **按 Plan 步骤逐一实现**
2. **实现过程中如有 UI 细节不确定，主动通过 Figma 回查**
3. **完成后输出变更文件清单**

## 通用编码规范

### 错误处理
- 网络请求/异步操作必须有 try-catch + loading/error 状态处理
- 用户可见的错误信息走国际化，日志用英文
- 避免静默吞掉异常，至少输出日志

### 屏幕适配
- 使用项目统一的适配方案，不要硬编码像素值；适配单位只负责尺寸换算，不等于自适应

### 页面布局
- **主体默认自适应**：页面、卡片、弹窗、面板和文案区的宽度由父约束或最大宽度控制，高度由内容撑开；不要照抄 Figma 同时固定宽高
- **局部元素允许固定**：图标/SVG、头像、插画、缩略图、拖拽条、角标和明确尺寸的小按钮可以固定宽高，但紧约束必须局限在元素自身
- **小图标按钮分层约束**：外层按钮/交互区域和内层图标视觉尺寸分别约束，图标居中并保持比例；不要让小图标继承 stretch、弹性填满或无界约束
- **图文同行**：图标保持固定，文案区域使用弹性约束；默认允许换行，只有设计明确要求单行时才缩小兜底
- **剩余空间**：空态居中、动态 Banner、可变头部应依据容器实际剩余空间，禁止用屏幕高度减一串固定常量推算
- **滚动与固定底栏**：固定底栏只使用局部层叠布局，滚动内容必须预留底栏和安全区空间；弹窗/面板自然撑开并提供最大高度滚动兜底
- **安全区域**：页面级必须处理安全区域（刘海/底部指示条）

### 颜色
- 优先使用项目颜色常量，不要硬编码色值
- 如果项目颜色管理中没有，先添加再使用

### 字体
- 优先使用项目字体管理方法/常量
- 不要直接硬编码字体样式

## 完成后

输出变更文件清单，**等待负责人检查自测**：
- 负责人进行功能自测、UI 走查、边界场景验证

## 提交前自检清单

- [ ] 所有新文件已正确导入，无遗漏依赖

- [ ] 图片资源已放入正确目录并遵循倍率规范
